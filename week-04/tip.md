# Tips for this week

This week I focused heavily on improving the application’s accessibility and making sure it would be more suitable for the type of users expected in an NHS environment. At this stage, I wanted the project to move beyond just a basic interface and start reflecting the real needs of patients and visitors, including people who may have visual difficulties, language barriers, or limited confidence with technology. Because of this, I spent time developing features that would make the application more inclusive and practical in a real-world hospital setting.
A major part of my work this week was adding accessibility-related features to the application. This included functions such as screen reading support and text resizing, which were designed to make the interface easier to use for people with different needs. I saw this as an important contribution because accessibility was not something that should be left until the end of the project. By beginning this work earlier, I helped ensure that these features were being built into the structure of the application rather than added as an afterthought.


I also worked on language support. My approach was to introduce local language support for key languages so that the application would still be usable even if the hospital Wi-Fi connection became unreliable. This was particularly relevant to the context of the project, because hospitals can be difficult environments for connectivity and users may already be under stress. In addition to this, I explored the use of Google Translate as a fallback for languages not already built into the system. I considered this a balanced approach, as it helped expand the application’s usefulness while still prioritising reliability and consistency for the main supported languages.
Alongside this, I created a staff portal and a settings page. These additions were important because they began to separate the needs of different user types within the system and made the application feel more complete and more realistic as a working product. I also saw this work as giving the team a stronger foundation before sprint week, as it meant there was already a usable structure in place for others to build on and refine.

Overall, this week was one of the most important stages so far because it helped shape the application into something that was more than just functional. My work contributed to making it more accessible, more resilient, and more suitable for the intended users. Looking back, this week reinforced for me that good software in a healthcare context needs to be designed not only around features, but around usability, inclusivity, and reliability.
